Professional Self-Assessment

Enhancement One — Software Engineering and Design

Enhancement One Resources Original Source Code (ZIP) Enhanced Source Code (ZIP) Download Enhancement One Narrative (Word)

The artifact I selected is Travlr Getaways, a full-stack web application originally created in CS 465 Full Stack Development I. Travlr was developed using the MEAN stack—MongoDB, Express, Angular, and Node.js—and includes a customer-facing website and an administrative interface for managing trip information. I selected this artifact for my ePortfolio because it demonstrates several of my software development skills within one application, including REST APIs, CRUD operations, authentication, database communication, client-side development, and server-side programming.

For this enhancement, I focused on improving the application's security, validation, error handling, and overall design. During my code review, I discovered a direct POST route in app.js that allowed trip creation without passing through the JWT-protected API router. I removed this route so protected operations now require authentication. I also strengthened JWT validation, added reusable server-side trip validation, improved error handling so internal errors are not exposed to users, and expanded Angular form validation. Authentication was improved by strengthening PBKDF2 password hashing, normalizing email addresses, validating registration information, using safer authentication responses, and simplifying the login form to require only the information actually needed. These changes demonstrate progress toward Outcomes 2, 3, 4, and 5, particularly the outcomes involving software engineering practices and developing a security mindset. My outcome-coverage plan remains the same, with Outcome 1 being addressed more directly through other areas of my final ePortfolio.

The enhancement process taught me that an application can function correctly while still containing design and security weaknesses. One challenge was making security improvements without breaking existing functionality because authentication, routing, the Angular interface, and the API are connected. I tested each major change by confirming that the server and MongoDB started correctly, existing trips loaded, a new user could register and log in, invalid trip information was rejected, and a valid trip could still be created. I also attempted to create a trip directly through the API without a JWT, and the server correctly rejected the request with an authorization error. This process helped me better understand defensive programming and showed how my approach to development has progressed from simply making software work to considering its security, maintainability, and reliability.

Enhancement Two — Algorithms and Data Structures

Enhancement Two Resources Enhanced Source Code (ZIP) Download Enhancement Two Narrative (Word)

The artifact I selected is Travlr Getaways, a full-stack web application originally created in CS 465 Full Stack Development I. Travlr was developed using the MEAN stack, which includes MongoDB, Express, Angular, and Node.js. The application includes a customer-facing website and an administrative interface used to manage trip information. I selected Travlr for this enhancement because the application gave me an opportunity to improve how trip data is searched, sorted, and retrieved while demonstrating my understanding of algorithms and data structures.

For this enhancement, I focused on improving the original trip-retrieval process. Previously, the application used Trip.find({}) to retrieve every trip from MongoDB and return the entire collection to the client. While this worked with a small number of records, it would become inefficient as the database grew. I enhanced the application by implementing server-side searching, filtering, sorting, and pagination. Users can now search trips by name, code, or resort, sort results by several approved fields in ascending or descending order, and navigate through smaller pages of results instead of retrieving the entire collection at once. I also added pagination metadata and updated the Angular interface so users can interact with these features. The enhancement demonstrates progress toward Course Outcomes 3 and 4 because I designed and implemented a more efficient computing solution using algorithmic principles while considering performance, scalability, and usability. My overall outcome-coverage plan has not changed because the other course outcomes are being demonstrated through other areas of my ePortfolio.

The enhancement process helped me better understand that algorithms are not limited to complicated mathematical problems. Decisions about how data is searched, sorted, limited, and returned can have a major effect on the performance and scalability of an application. One challenge was that changing the API response affected multiple parts of the application. The backend originally returned a simple array of trips, but the enhanced version needed to return the trip data along with pagination and search information. Because of this, I also had to modify the Angular service and trip-listing component so the front end could correctly process the new response. I tested the enhancement by searching for specific trips, changing the sorting order, and navigating across multiple pages of results. I also tested invalid values, including a negative page number, an excessive page size, and an unsupported sorting field. The application safely handled each condition by applying appropriate defaults and limits. Overall, this enhancement strengthened my understanding of designing algorithms that not only produce correct results but also consider efficiency, boundary conditions, security, and how different parts of a full-stack application work together.

Enhancement Three — Databases

Enhancement Three Resources Enhanced Source Code (ZIP) Download Enhancement Three Narrative (Word)

The artifact I selected for this enhancement is the Travlr Getaways full-stack web application that I originally created in CS 465: Full Stack Development I. The application was developed using the MEAN stack, which includes MongoDB, Express, Angular, and Node.js. It includes a customer-facing travel website and an administrative interface that allows authorized users to add, edit, view, and delete trip information. I previously enhanced this same artifact for the software design and engineering and algorithms and data structures categories. For this milestone, I focused specifically on improving the database portion of the application.

I selected Travlr Getaways for the database category because MongoDB is an important part of the application's functionality. The trip information displayed by the application is stored in the database and accessed through the REST API. This gave me an opportunity to demonstrate my ability to improve how an application validates, stores, retrieves, and protects its data. One of the main improvements I made was strengthening the Mongoose trip schema. I added database-level validation for required fields, minimum and maximum lengths, and valid values. I also changed the perPerson field from a string to a number so that price information would be stored and processed using a more appropriate data type. The price field now prevents negative values from being accepted. I also added timestamps to the records and indexes for commonly queried fields, including the resort and start date. The trip code uses a unique index to help prevent duplicate records from being stored.

I also updated the controller so that incoming prices and dates are validated and converted before they are stored in MongoDB. Duplicate trip codes now produce a controlled response rather than allowing duplicate data to be added. I preserved the search, filtering, sorting, and pagination functionality that I developed during my algorithms and data structures enhancement as well. I felt this was important because I wanted each enhancement to build on the previous version instead of removing functionality that I had already completed. I also updated the Angular model and administrative forms so that the front end treats the price as a number and prevents a negative price from being submitted. Together, these changes improved the reliability of the database and the overall data integrity of the application.

This enhancement met the course outcomes I originally planned to address, particularly Course Outcomes 3, 4, and 5. For Course Outcome 3, I evaluated how the application retrieves and organizes data and used indexing, pagination, filtering, and appropriate data types to improve the solution while considering the design choices involved. For Course Outcome 4, I used MongoDB, Mongoose, Angular, and Node.js techniques to implement database improvements that provide value to the application. For Course Outcome 5, I strengthened validation and data integrity by preventing invalid prices, validating dates and required information, handling duplicate trip codes, and limiting the types of values that can be stored in the database. I do not need to make a major change to my original outcome-coverage plan because this enhancement strengthened my evidence for Outcomes 3, 4, and 5, while my other enhancements and professional self-assessment will help demonstrate the remaining course outcomes throughout my completed ePortfolio.

The process of completing this enhancement helped me better understand that database development involves more than simply storing and retrieving information. The way data is structured and validated can affect the reliability of the entire application. Changing the price field to a numeric data type was a good example of this because the change affected more than just the database. The MongoDB schema, API controller, Angular model, and forms all needed to agree on how the value was handled. This showed me how closely connected the different parts of a full-stack application are and why changes need to be tested throughout the entire application.

One challenge I encountered involved testing the unique trip code. During testing, I had to make sure the database indexes were synchronized correctly and remove an extra test record before verifying the final result. Working through this helped me better understand how Mongoose schema definitions and MongoDB indexes work together. I also tested the application with a negative price and confirmed that the enhanced validation prevented the invalid value from being submitted. Overall, this enhancement gave me more experience working across the different layers of a full-stack application while keeping the database at the center of the improvement. It also reinforced the importance of testing after making database changes because something as simple as changing a data type or validation rule can affect the database, API, and user interface. The skills I practiced during this enhancement will be useful as I continue developing my technical abilities and move further into networking, systems, and enterprise technology.
